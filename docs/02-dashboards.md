# Дашборды Power BI

Отчёт собран на прямом подключении к PostgreSQL (`consolidation_planner`) и состоит из двух
страниц: два дашборда под разные аудитории. Это сделано в силу того, что у аудиторий разные вопросы: бизнесу нужно «что происходит и сколько это стоит»,
отделу закупок нужно видеть основные метрики, на которые они могут ориентироваться более локально.

## Страница «Для бизнеса»

<img width="1584" height="907" alt="image" src="https://github.com/user-attachments/assets/47dd9bd7-1b8a-455e-8c29-1b3511c28fd6" />


Обзорный срез для совещаний.

**Состав:**

- подпись источника и периода: схема, диапазон дат, дата обновления;
- KPI-строка: загрузка контейнеров, резерв контейнеров %, контейнеров сверх нормы, заказов;
- блок отклонения: ограничивающий фактор, цель загрузки, разрыв в п.п., отправок ниже порога;
- фильтры: порт назначения, год-месяц, тип контейнера;
- **Использование грузоподъёмности и объёма по типу контейнера** — гистограмма с линией цели 85%;
- **Загрузка по типу контейнера** — линейчатая с целевой линией;
- **Загрузка по месяцам** — линия с подписями, показывает устойчивость проблемы;
- **«Что говорят данные»** — текстовый блок, заполняется вручную перед совещанием.

**Про текстовый блок.** Это сознательное решение. Три тезиса пишутся руками под конкретную встречу: цифры дашборд
отдаёт сам, а интерпретацию и акцент всё равно выбирает человек исходя из повестки.
Так дашборд не превращается в стену графиков, которую каждый читает по-своему.

## Страница «Для отдела закупок»

Рабочий срез. Сюда вынесены те показатели, с которыми отдел может что-то сделать прямо сейчас;
при необходимости картина расширяется.

**Состав:**

- фильтры: год-месяц, поставщик, порт назначения, тип контейнера;
- та же KPI-строка — чтобы оба дашборда читались в одних числах;
- **Распределение отправок по загрузке** — гистограмма по корзинам 10%, показывает,
  что недогруз это режим, а не выбросы;
- **Отправки по поставщику** — проверка поставщиков, с которыми работаем чаще и у которых отгружаемся чаще;
- **Загрузка по порту назначения** с целевой линией — проверка версии про направления;
- **Плотность, кг/м³ по номенклатуре** — объясняет, почему 40DC упирается в вес;
- **Сводная таблица по типам контейнеров**: отправки, загрузка, объём, вес, ограничивающий
  фактор, стоимость доставки ₽/кг. Здесь видно главное противоречие: 20GP хуже загружен
  и при этом дороже за килограмм.

## Обработка данных (Power Query)

- подключение к PostgreSQL в режиме импорта, отбор нужных таблиц схемы;
- приведение типов: `load_factor_volume`, `load_factor_weight`, `f_score` — в десятичное число
  с процентным форматом;
- объединение `consolidations` со справочником `container_types` (тип контейнера) и
  `transport_costs` (ставка фрахта, стоимость за кг);
- таблица **Календарь** из даты отправки — для корректной сортировки динамики;
- расчётный столбец **корзина загрузки**: округление `f_score` вниз до десятых —
  основа гистограммы распределения;

## Меры (DAX)

```dax
Загрузка контейнеров   = AVERAGE(consolidations[f_score])
Использование объёма   = AVERAGE(consolidations[load_factor_volume])
Использование грузоподъёмности = AVERAGE(consolidations[load_factor_weight])

Цель загрузки          = 0.85
Отклонение до цели     = [Цель загрузки] - [Загрузка контейнеров]
Подпись отклонения     = FORMAT([Отклонение до цели] * 100, "0") & " п.п. до цели"

Резерв контейнеров, %  = 1 - DIVIDE([Загрузка контейнеров], [Цель загрузки])
Контейнеров сверх нормы =
    COUNTROWS(consolidations)
    - ROUND(DIVIDE(COUNTROWS(consolidations) * [Загрузка контейнеров], [Цель загрузки]), 0)

Отправок ниже порога   = CALCULATE(COUNTROWS(consolidations), consolidations[f_score] < 0.4)
Заказов                = DISTINCTCOUNT(consolidation_orders[order_id])

Стоимость доставки ₽/кг = DIVIDE(SUM(transport_costs[cost_rub]), SUM(consolidations[total_weight_kg]))
Плотность, кг/м³        = DIVIDE(SUM(product_boxes[weight_kg]), SUM(product_boxes[volume_m3]))

Ограничивающий фактор  =
    SWITCH(TRUE(),
        [Использование грузоподъёмности] >= [Использование объёма], "Упирается в вес",
        "Недобор")
```

**Логика двух расчётных KPI.**
*Резерв контейнеров* — доля парка, которая не понадобилась бы при загрузке до цели:
`1 − 56% / 85% ≈ 35%`.
*Контейнеров сверх нормы* — то же в штуках: 76 фактических против 50 необходимых = **26**.
Эти две меры переводят проценты загрузки в язык, понятный бизнесу: оплаченные контейнеры.
